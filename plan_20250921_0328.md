# Comprehensive Development Plan - Ibn Al Arab (2025-09-21 03:28 AM)

This document outlines a detailed plan for implementing the meal plan selection and checkout feature, user profile management, user/admin dashboards, and addressing identified bugs, based on a thorough review of the existing codebase and specific requirements.

## Product Feature Groups / Workflows:

### 1. Core Subscription & Checkout Workflow

*   **Goal:** Enable users to select a meal plan, provide necessary details (delivery, student status), and complete a subscription order.
*   **Dependencies:** User Authentication, Plan Data, User Profile, Database.

    *   **1.1. Dynamic Pricing Display on Homepage (`MealPlanPreview.tsx`):**
        *   **Description:** Modify `client/components/sections/MealPlanPreview.tsx` to dynamically show either the regular price (`plan.priceAED`) or the student price (`plan.studentPriceAED`) based on the authenticated user's `is_student` status from their profile. If not logged in, show regular price.
        *   **Changes:** Integrate `useAuth` hook, conditional rendering for prices.
        *   **Translations:** Ensure price labels are translated.

    *   **1.2. Checkout Page Enhancements (`Checkout.tsx`):**
        *   **Description:** Refine the checkout page to handle dynamic pricing, collect delivery and student verification details, and process order submission.
        *   **Changes:**
            *   **Authentication Gate:** Implement a check using `useAuth`. If `user` is null, redirect to `/login` or `/register`.
            *   **Dynamic Pricing Calculation:** Adjust `originalPrice` and `discountedPrice` calculations to use `plan.priceAED` or `plan.studentPriceAED` based on the authenticated user's `profile?.is_student` status. If the user is not logged in, or not a student, the `priceAED` should be used.
            *   **Delivery Information Collection:**
                *   Add a mandatory dropdown for "Sharjah districts" (hardcoded list). This will be used to populate the `district` field in `user_addresses`.
                *   Add an open text input field for "Address" (optional), mapping to `formatted_address` in `user_addresses`.
                *   These fields will be used to create/update an entry in the `user_addresses` table and link to the `subscriptions` table.
            *   **Student Confirmation:**
                *   Add input fields for "University Email" and "Expiry Date" (for student ID).
                *   These fields will update the user's `profiles` table (`university_email`, `student_id_expiry`, and set `is_student` to `TRUE`).
            *   **Renewal Preference:** Add a dropdown for "Renewal preference" (Select/Automatic/Manual). This will need a new column in the `subscriptions` table, e.g., `renewal_type`.
            *   **Payment Method Selection:**
                *   Display "Local Wire Transfer with Proof Upload" as active.
                *   Display "Credit Card" as dimmed/disabled ("Coming Soon").
                *   For Wire Transfer, provide bank details and an interface for file upload (PDF/images). The uploaded file's URL will be stored in the `receipt_url` field of the `payments` table.
            *   **Order Submission:** On "Pay Now" click,
                *   Validate all required fields.
                *   Create/update `user_addresses` entry.
                *   Update `profiles` with student info if provided.
                *   Insert a new record into the `subscriptions` table with `status: 'pending_payment'`.
                *   Insert a new record into the `payments` table with `method: 'wire_transfer'`, `status: 'pending'`, and `proof_url` (from file upload).
                *   Redirect to a confirmation page or user dashboard.
        *   **Translations:** Add translations for all new UI text (Sharjah districts, address, university email, expiry date, payment methods, renewal preference, etc.).
