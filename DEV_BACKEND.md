Dev backend run instructions

Required env vars (create `.env` at project root):
- SUPABASE_URL
- SUPABASE_ANON_KEY
- SUPABASE_SERVICE_ROLE_KEY
- REQUIRE_AUTH (set to `false` for local dev if you want to allow POST with `user_id` payload)

Build and run (recommended, deterministic):
1. Build the backend:
   ```bash
   npm run build:backend
   ```
2. Run the compiled server (production/dev):
   ```bash
   node dist/backend/server.js
   ```

Dev auto-reload (uses build+node):
- `npm run dev:backend` — watches `backend/**/*.ts`, runs `npm run build:backend` on change, then runs `node dist/backend/server.js`.

Alternate (run TypeScript directly):
- `npm run dev:backend:ts` (uses `npx ts-node-esm backend/server.ts`) — useful for quick iteration but may behave differently across machines.

Troubleshooting:
- If you see `ERR_MODULE_NOT_FOUND` for internal imports, run the `build:backend` command and then run the compiled `node dist/backend/server.js` directly.
- Ensure `.env` contains the `SUPABASE_SERVICE_ROLE_KEY` (server needs it to upsert protected tables).
- If `REQUIRE_AUTH` is `true`, endpoints that require auth will return 401 unless a valid Authorization Bearer token is provided.

Notes:
- Do not edit files under `dist/` — they are generated by `tsc` and will be overwritten on build.
